## 1. 项目概述

### 1.1 项目简介

GhostJ 是一个基于 Java 开发的**远程访问工具(RAT - Remote Access Tool)**平台，实现了以下核心功能：

- ✅ 实时执行命令行指令
- ✅ 屏幕截图与监控
- ✅ 文件上传/下载/浏览
- ✅ 鼠标键盘控制
- ✅ 录音功能
- ✅ 进程管理
- ✅ 操作监控与日志

### 1.2 三层架构

```
┌──────────────────────────────────────────────────────────────┐
│                        GhostJ 架构                            │
├─────────────────┬──────────────────┬─────────────────────────┤
│   CLIENT 端     │    SERVER 端     │      MASTER 端          │
│   (被控端)      │    (中转服务器)  │      (主控端)           │
├─────────────────┼──────────────────┼─────────────────────────┤
│ 配置: ghostjc.ini│ 配置: ghostjs.ini│ 配置: gmaster.ini      │
│ 入口: ClientMain│ 入口: ServerMain │ 入口: MasterMain        │
│ 网络: HandleConn│ 网络: AcceptConn │ 网络: CreateConn        │
│ 命令: Processor │ 转发: TransCmd   │ GUI: InitGUI            │
│ 功能: 20+ Func* │ 管理: HandleConn │ 显示: ScreenDisplay     │
└─────────────────┴──────────────────┴─────────────────────────┘
```

### 1.3 协议设计

GhostJ 使用自定义的文本协议，分为两个级别：

| 级别 | 前缀 | 执行位置 | 示例 |
|------|------|----------|------|
| Server级 | `!` | 在 Server 端执行 | `!list`, `!focus &3` |
| Client级 | `!!` | 转发到 Client 端执行 | `!!scr screen.jpg`, `!!info` |

**数据流向:**
```
Master → [!list] → Server → 返回在线客户端列表
Master → [!!scr] → Server → 转发到 Client → 截图并上传 → Server → Master
```

```java
public class Processor extends AbstractProcessor {
    @Override
    protected Command parse(String cmdStr) {
        // 解析 "!!cmd param1 param2" 格式
        String[] spt = cmdStr.split(" ");
        return new Command(spt[0], subArray(spt,1,spt.length), cmdStr);
    }
}
```

**HandleConn.java** - 连接处理类
```java

    public static String ip;              // ⚠️ 静态
```

```
AbstractProcessor (抽象类)
    ├── parse(String cmdStr) → Command  [抽象方法]
    ├── run(String cmdStr)              [模板方法]
    └── registerFunc(...)               [注册功能]
         ↓
    Processor (具体实现)
         ↓
    parse() 解析字符串 → Command对象
         ↓
AbstractFunc (命令接口)
    ├── run(Command cmd)
    ├── match(String cmd)
    └── getHelp()
         ↓
    20+ 具体功能实现:
    ├── FuncPrtScr    - 截图

    └── ...
```

**优点**: ✅ 使用了策略模式，易于扩展新命令

## 5. 设计模式应用

### 5.1 已使用的设计模式

#### ✅ 策略模式 (Strategy Pattern)
**位置**: `client.cmd` 包

```java
// 抽象策略
public abstract class AbstractFunc {
    public abstract void run(Command command);
    public abstract boolean match(String cmd);
    public abstract String getHelp();
}

// 具体策略
public class FuncPrtScr extends AbstractFunc { ... }
public class FuncAudio extends AbstractFunc { ... }
// ... 20+ 实现类

// 上下文
public class AbstractProcessor {
    ArrayList<AbstractFunc> funcList = new ArrayList<>();
    
    public void run(String cmdStr) {
        Command cmd = parse(cmdStr);
        for(AbstractFunc func : funcList) {
            if(func.match(cmd.getCmd())) {
                func.run(cmd);
                return;
            }
        }
    }
}
```

**优点**: 
- ✅ 易于添加新命令
- ✅ 命令逻辑封装良好

#### ✅ 模板方法模式 (Template Method)
**位置**: `AbstractProcessor`

```java
public abstract class AbstractProcessor {
    protected abstract Command parse(String cmdStr);  // 子类实现
    
    public void run(String cmdStr) {  // 模板方法
        Command command = parse(cmdStr);  // 调用子类实现
        // 执行命令的通用逻辑
    }
}
```

#### ⚠️ 单例模式 (滥用!)
**位置**: 所有 `*Main` 类

```java
public class ClientMain {
    public static Processor processor = new Processor();
    // 实际上是隐式单例，但没有私有构造函数控制
}
```

**问题**: 
- ❌ 非线程安全
- ❌ 无法控制实例化
- ❌ 难以测试

## 6. 代码质量问题

### 6.1 严重问题 (🔴 Critical)

#### 问题1: 静态字段泛滥 (40+ 个)

**影响**: 
- ❌ 无法进行单元测试
- ❌ 线程不安全
- ❌ 隐式依赖，难以追踪
- ❌ 内存泄漏风险

**示例**:
```java
// ServerMain.java
public static ArrayList<HandleConn> socketArrayList = new ArrayList<>();
// ⚠️ 问题: ArrayList 非线程安全，多线程并发添加/删除会出错!
```

**修复建议**:
```java
// 使用依赖注入
public class ServerMain {
    private final ConnectionManager connectionManager;
    private final Config config;
    
    public ServerMain(ConnectionManager cm, Config cfg) {
        this.connectionManager = cm;
        this.config = cfg;
    }
}

// 线程安全的连接管理
public class ConnectionManager {
    private final ConcurrentHashMap<String, HandleConn> connections;
    
    public void addConnection(String id, HandleConn conn) {
        connections.put(id, conn);
    }
}
```

#### 问题2: 重复代码 (9个重复类)

**统计**:
```
Config.java    - 3个副本 (99/102/83 行)
FileRW.java    - 3个副本 (52/59/? 行)
Out.java       - 3个副本
────────────────────────────────
总计:          - 9个重复文件
估计重复行数:  - ~600 行
```

**修复建议**:
```
1. 保留 /util/Config.java 作为基类
2. 如需扩展，创建子类:
   class ClientConfig extends Config { 
       public Object remove(String key) { ... }
   }
3. 删除 client/util/Config.java 和 master/util/Config.java
4. 同样处理 FileRW 和 Out
```

#### 问题3: 异常处理不当

**反模式示例**:
```java
// 1. 吞掉异常
try {
    // 重要操作
} catch(Exception e) {
    // 什么也不做! ⚠️
}

// 2. 只打印不处理
catch(Exception e) {
    e.printStackTrace();  // 继续执行，可能导致更严重问题
}

// 3. 捕获过于宽泛
catch(Exception e) {  // 应该捕获具体异常类型
    ...
}
```

**统计**: 约 50+ 处不当异常处理

**修复建议**:
```java
// 使用具体异常类型
try {
    socket.connect();
} catch(SocketTimeoutException e) {
    logger.error("连接超时: {}", e.getMessage());
    reconnect();
} catch(IOException e) {
```

```java
            // 工作逻辑
        }
        // 清理资源
    }
}
```

```java
private static final Set<String> ALLOWED_COMMANDS = Set.of("dir", "ipconfig", ...);

public Process exec(String command) {
    String cmd = command.split(" ")[0];
    if(!ALLOWED_COMMANDS.contains(cmd)) {
        throw new SecurityException("命令不在白名单中");

    ProcessBuilder pb = new ProcessBuilder(command.split(" "));

    return pb.start();
}
```
